# DynamoRIO ChampSim Tracer

This project implements a ChampSim-compatible tracer using DynamoRIO instead of Intel PIN. This enables trace generation on multiple architectures including x86, x86-64, ARM32, ARM64 (AArch64), and RISC-V.

## Overview

ChampSim is a trace-driven simulator that originally used Intel PIN for generating instruction traces. This project replaces PIN with DynamoRIO, which offers:

- **Multi-architecture support**: x86, x86-64, ARM, AArch64, RISC-V
- **Open-source**: BSD license
- **Active development**: Regular updates and maintenance
- **Cross-platform**: Linux, Windows, macOS, Android

## Trace Format

The tracer generates binary traces in the same format as the original ChampSim PIN tracer. Each instruction record contains:

- **Instruction Pointer (IP)**: 64-bit address
- **Branch Information**: Whether the instruction is a branch and if it was taken
- **Source Registers**: Up to 4 source register IDs
- **Destination Registers**: Up to 2 destination register IDs
- **Source Memory Addresses**: Up to 4 memory read addresses
- **Destination Memory Addresses**: Up to 2 memory write addresses

Each instruction is 64 bytes in the trace file.

## Prerequisites

### Installing DynamoRIO

#### From Release (Recommended)

Download the latest DynamoRIO release for your platform:

```bash
# For Linux x86-64
wget https://github.com/DynamoRIO/dynamorio/releases/download/release_10.0.0/DynamoRIO-Linux-10.0.0.tar.gz
tar xzf DynamoRIO-Linux-10.0.0.tar.gz
export DYNAMORIO_HOME=$(pwd)/DynamoRIO-Linux-10.0.0
```

#### Building from Source

For architectures like ARM or RISC-V, or for the latest features:

```bash
git clone https://github.com/DynamoRIO/dynamorio.git
cd dynamorio
mkdir build && cd build
cmake ..
make -j$(nproc)
export DYNAMORIO_HOME=$(pwd)
```

For cross-compilation (e.g., for ARM on x86):

```bash
# ARM32
cmake -DCMAKE_TOOLCHAIN_FILE=../make/toolchain-arm32.cmake ..

# AArch64
cmake -DCMAKE_TOOLCHAIN_FILE=../make/toolchain-arm64.cmake ..

# RISC-V (requires appropriate toolchain)
cmake -DCMAKE_TOOLCHAIN_FILE=../make/toolchain-riscv64.cmake ..
```

## Building the Tracer

```bash
mkdir build
cd build
cmake -DDynamoRIO_DIR=$DYNAMORIO_HOME/cmake ..
make
```

This will generate `libchampsim_tracer.so` (or `.dll` on Windows).

## Usage

Basic usage:

```bash
$DYNAMORIO_HOME/bin64/drrun -c ./libchampsim_tracer.so -- <your_program> [args]
```

### Command-line Options

- **`-o <filename>`**: Output trace file name (default: `champsim.trace`)
- **`-s <number>`**: Number of instructions to skip before tracing begins (default: 0)
- **`-t <number>`**: Number of instructions to trace (default: 1,000,000)

### Examples

Trace 200,000 instructions of `ls`, skipping the first 100,000:

```bash
$DYNAMORIO_HOME/bin64/drrun -c ./libchampsim_tracer.so \
  -o traces/ls_trace.champsim -s 100000 -t 200000 -- ls -la
```

Trace a SPEC CPU benchmark:

```bash
$DYNAMORIO_HOME/bin64/drrun -c ./libchampsim_tracer.so \
  -o traces/mcf.champsim -s 30000000000 -t 200000000 -- ./mcf_base.gcc inp.in
```

### Compressing Traces

Traces are approximately 64 bytes per instruction but compress well:

```bash
xz -9 traces/ls_trace.champsim
# Result: traces/ls_trace.champsim.xz (typically <1 byte per instruction)
```

## Architecture-Specific Notes

### x86/x86-64

Fully supported with the same semantics as the original PIN tracer.

### ARM32/AArch64

- Register numbering follows DynamoRIO's ARM register conventions
- NEON/SIMD registers are tracked
- Thumb mode is supported

### RISC-V

- Requires DynamoRIO built with RISC-V support
- Currently in experimental stage in DynamoRIO
- Both RV32 and RV64 variants supported

## Differences from PIN Tracer

1. **Register IDs**: DynamoRIO uses different register ID encoding than PIN. The register numbers in traces will differ but maintain the same semantic information.

2. **Performance**: DynamoRIO generally has lower overhead than PIN, resulting in faster trace generation.

3. **Architecture Support**: DynamoRIO supports ARM and RISC-V, which PIN does not.

## Compatibility with ChampSim

Traces generated by this tool are binary-compatible with ChampSim and can be used directly with the simulator. The trace format matches the `input_instr` structure defined in ChampSim's `trace_instruction.h`.

## Building for Multiple Architectures

### Cross-compilation Example for ARM64

```bash
# Install cross-compiler
sudo apt-get install gcc-aarch64-linux-gnu g++-aarch64-linux-gnu

# Build DynamoRIO for ARM64
cd dynamorio/build_arm64
cmake -DCMAKE_TOOLCHAIN_FILE=../make/toolchain-arm64.cmake ..
make -j$(nproc)

# Build tracer for ARM64
cd ../../build_arm64
cmake -DDynamoRIO_DIR=../dynamorio/build_arm64/cmake \
      -DCMAKE_TOOLCHAIN_FILE=../dynamorio/make/toolchain-arm64.cmake ..
make
```

## Troubleshooting

### DynamoRIO not found

Ensure `DYNAMORIO_HOME` is set and points to your DynamoRIO installation:

```bash
export DYNAMORIO_HOME=/path/to/dynamorio
cmake -DDynamoRIO_DIR=$DYNAMORIO_HOME/cmake ..
```

### Trace file not created

- Check file permissions in the output directory
- Verify the target program runs successfully under DynamoRIO without the tracer
- Check DynamoRIO logs (set `DYNAMORIO_OPTIONS="-stderr_mask 0xc"`)

### Performance issues

- Increase the skip count (`-s`) to avoid tracing initialization code
- Reduce the trace count (`-t`) for initial testing
- Use parallel compression for large traces
